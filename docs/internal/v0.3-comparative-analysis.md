# peer-orchestra v0.3 — Comparative Analysis

> **Status — superseded in part, 2026-08-27.** Commit `67744f3` fixed the hook
> defects described below *before* `0.3.0` was published. All four hooks now emit
> the correct `hookSpecificOutput` envelope; the persona loader injects the persona
> body (verified at 2829 chars from the published tarball); the router reads
> `user_prompt`. Sections stating these as current describe pre-fix code.
> Still live: unanchored keyword matching in `agent-router.py:104`.

**Date:** 2026-08-27 · **Analysed:** v0.2.0 (`main`) · **Method:** four parallel research agents (architecture, Claude Code native capabilities, real-world GCT failures, competitor frameworks), every load-bearing claim re-verified directly against this machine.

---

## The conclusion

**peer-orchestra's orchestration layer has been superseded by native Claude Code features. Its doctrine layer is the real asset — and that layer currently never reaches the model.**

Two independent facts drive everything below:

1. **Claude Code now ships agent teams, cross-session messaging, and a liveness API natively.** Not theoretically — verified on this machine.
2. **peer-orchestra's own plumbing is inert.** Three of four hooks emit a JSON shape Claude Code discards; the "persona loader" never reads the persona.

The tool's genuine value — the persona corpus, the dispatch doctrine, the transcript→memory loop — is real and portable. The scaffolding around it is building against a deadline.

---

## Part 1 — What peer-orchestra actually is

`npx peer-orchestra init` is **a file copier that exits.** No daemon, no runtime, no supervision. 1,617 lines, zero runtime dependencies.

The decisive split:

| Enforced by code | Requested in prose |
|---|---|
| Node ≥18 check, exit 5 | "Never code directly as orchestrator" |
| Unparseable settings.json → exit 6 before any write | "Max 3 rework attempts — never retry a 4th time" |
| Files preserved unless `--force` | "NEVER skip a quality gate" |
| Theme switch removes stale personas | "Check peer status before dispatching" |
| Agent-name path sanitisation | Dispatch template, `<300 words`, mandatory priority |
| Memory idempotency, `.gitignore` safety | The entire team protocol |

**Every enforced behaviour is about installing files safely. Every behaviour about how agents collaborate is prose.** Nothing counts retries. Nothing evaluates a gate. Nothing detects non-compliance.

### The dispatch is never executed by peer-orchestra

`commands/dispatch.md` is not a program — it is a prompt telling the model to call `send_message` / `list_peers`. Those tools belong to the third-party `claude-peers` MCP, which is **not an npm dependency, not installed by `init`, and not version-checked**. peer-orchestra ships the etiquette for a transport it does not own.

## Part 2 — The plumbing is inert (verified by running it)

### 2a. Hook output uses a key Claude Code ignores

```
peer-orchestra:  {"hookEventName": …, "message": …}
GCT (working):   {"hookSpecificOutput": {"hookEventName": …, "additionalContext": …}}
```

The templates are the GCT originals **flattened during generalisation** — nesting dropped, `additionalContext` renamed to `message`. `message` is not a recognised key.

**Consequence: the self-learning loop writes to SQLite correctly, reads back correctly, then drops the result at the final inch.** Highest-leverage fix in the repo; roughly one line per hook.

### 2b. The persona loader never loads the persona

```
emitted:       118 bytes   "Agent persona loaded: zhongli (rules: …)"
persona file: 2,738 bytes  ← never opened
```

It announces a filename. And `.claude/rules/` is **not** a directory Claude Code auto-loads. So a persona reaches context only if the orchestrator remembers to write `SETUP: Read .claude/rules/agent-X.md` into a dispatch *and* the receiving model complies.

**Identity is not established by the identity mechanism.** It is established by one agent politely asking another to read a file.

### 2c. The router is silent on every prompt

Reads `input_data["prompt"]`; Claude Code sends `user_prompt`. Fed the real payload shape: **zero output**.

Even if wired, the routing is noise — keywords are the first four words of each `## Abilities` bullet, matched by unanchored substring. "fix the database API performance" matched **8 of 11 agents** (`"base"` fires inside "data**base**").

### 2d. Memory stores inputs, not outcomes

**Correction to an earlier draft of this analysis.** A first pass reported `dev.db` as "283/283 pure heartbeat noise." That was wrong, and wrong in an instructive way: `dev.db` holds 283 rows but only **2 live** — the recall query filters `WHERE superseded_by IS NULL` (`session-start-peer-memory.py:55`), and the `persona_state` row is a correctly-implemented *rolling pointer* that supersedes its predecessor. It never displaces anything. GCT's own `lessons.md` records an architect agent falling into this exact trap ("506 of 943 rows are content-free stubs" — also wrong, same cause).

The real numbers, on live rows across the 12 persona DBs:

| | Count | Share |
|---|---|---|
| Live rows | **450** | 100% |
| `quality-gate-*` | **297** | **66%** |
| Genuinely other | 153 | 34% |

Of the quality-gate rows, ~86 are **verbatim dispatch text echoed back** — the prompt, not the outcome. Some are pure tool plumbing (`<task-id>`, `<tool-use-id>` captured as "knowledge"), and their topics carry an `unknown` date suffix, showing the topic generator itself fails.

The genuinely reusable ~30% is excellent:

```
correction-2026-05-20 | imp=0.9 | Docling 2.79 emits DocItemLabel.TEXT (NOT PARAGRAPH)
                                  for narrative paragraphs on real Tata...
```

**The diagnostic gap: the auto-extractor produces echoes; the hand-written `.claude/personas/lessons/*.md` files produce lessons.** Same agents, same sessions, two orders of magnitude difference in value density.

Also: four of twelve personas silently stopped writing months ago (`neuvillette` last written 2026-04-20), and nothing surfaced it.

## Part 3 — What Claude Code now does natively

Verified on this machine (Claude Code **2.1.247**):

| Native feature | Evidence | Replaces |
|---|---|---|
| **Agent teams** | `~/.claude/teams/session-*/config.json` with `leadAgentId`, `members[]`, `agentType`, `tmuxPaneId`, `cwd`, `subscriptions`, `backendType` | The entire terminal-per-agent topology |
| **Task lists** | **125** dirs under `~/.claude/tasks/`, file-locked claiming | `OUTPUT: {file path}` prose convention |
| **Cross-session messaging** | v2.1.224+, Unix domain socket, `$CLAUDE_CODE_MESSAGING_SOCKET` | The `claude-peers` MCP dependency |
| **Liveness** | `claude agents --json` → `pid`, `status: busy\|idle`, `cwd`, `sessionId` | peer-orchestra's blind spot — **it has no answer at all** |
| **Agent definitions** | **142** already in `~/.claude/agents/` | `.claude/rules/agent-*.md` |
| **Enforcing hooks** | `TeammateIdle`, `TaskCreated`, `TaskCompleted` — all block on exit 2 | Prose retry limits and quality gates |

**Timing:** agent teams are **experimental, opt-in** (`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`, not enabled in your settings). That is peer-orchestra's remaining window — not a reason it still has a technical edge.

### The verdict table

| peer-orchestra provides | Status | Native equivalent |
|---|---|---|
| Terminal-per-agent topology | **Redundant** | Agent teams |
| `PEER_AGENT` identity | **Redundant** | `agentType` in team config |
| claude-peers messaging | **Redundant** | Cross-session messaging (built in, socket-based) |
| `/party`, `/orchestra-status` | **Redundant** | Team roster + `claude agents --json` |
| Prompt routing | **Inert, and redundant** | Native subagent selection |
| Retry limits, quality gates | **Unenforceable as prose** | `TaskCompleted` / `Stop` hooks (exit 2 blocks) |
| **Themed persona corpus** | **GENUINE ASSET** | Native agents are a *format*, not content |
| **Dispatch doctrine** | **GENUINE ASSET** | Nothing native encodes it |
| **Transcript→memory loop** | **GENUINE GAP** | Native `memory:` field is per-agent config, not extraction |

## Part 4 — Borrowable patterns (no daemon required)

From CrewAI, AutoGen, LangGraph, OpenAI Agents SDK, claude-squad — filtered for what fits a tool with no runtime process:

| # | Pattern | Source | How it works here |
|---|---|---|---|
| 1 | **Liveness API** | claude-squad (pane hashing) → superseded | `claude agents --json`. Zero new infrastructure |
| 2 | **Enforced completion gates** | CrewAI guardrails | `Stop` hook exit 2 blocks "done" until the artifact exists. Converts *requested* rules into *enforced* ones. Must check `stop_hook_active` |
| 3 | **Structured handoffs** | OpenAI `input_type` | `PreToolUse` hook validates the payload against a JSON schema, returns `permissionDecision: "deny"` with the schema as the reason. Model retries with valid structure |
| 4 | **Bounded retry loop** | CrewAI `guardrail_max_retries` | `Stop` hook + validator, count in a status file |
| 5 | **Termination conditions** | AutoGen (11 composable classes) | Max-turns / timeout / token-budget predicates in a `Stop` hook |

**Not applicable:** LangGraph's coded graph and checkpointing, CrewAI's hierarchical manager, AutoGen's speaker selection — all require a process owning the loop. Do not build a DAG engine for a markdown scaffolder.

## Part 5 — Recommendations, ranked

### Tier 1 — Do regardless of direction (hours, high value)

| # | Change | Why |
|---|---|---|
| **1** | **Fix hook output to `hookSpecificOutput.additionalContext`** | One line per hook. Turns the entire memory loop from write-only to actually working. Nothing else competes on leverage |
| **2** | **Make the persona loader read the file** | Emit the 2,738 bytes, not a 118-byte announcement. The product's core asset currently never reaches context |
| **3** | **Fix the router input key** (`prompt` → `user_prompt`) — or delete the router | It is silent today. If kept, anchor keyword matching; 8-of-11 matches is worse than none |
| **4** | **Stop writing `persona_state` heartbeats to memory** | 283/283 rows in `dev.db` are noise that crowds out real recall |

### Tier 2 — The architectural decision

**Convert from npx scaffolder to a Claude Code plugin** shipping:
- Native agent definitions (`agents/*.md` with proper frontmatter) instead of `.claude/rules/` markdown
- The doctrine as **skills** (model-invocable) rather than prose nobody enforces
- The transcript→memory hook, fixed
- `TeammateIdle` / `TaskCreated` / `TaskCompleted` hooks as the **enforcement layer** on top of Anthropic's transport

This keeps what is genuinely peer-orchestra's (corpus, doctrine, learning loop) and drops what Anthropic now does better (transport, identity, liveness, spawning).

### Tier 2b — Convert doctrine into execution (see Part 7)

The highest-value items from five months of real failures, ranked:

1. **Worktree-per-agent as the default topology** — the one gap a prompt cannot close in principle. The rule existed for five months and collisions kept happening
2. **Typed finding records** — `{claim, probe_command, control_positive, control_negative}`. A count with no two-sided control should not render as a number. This addresses the single most frequent failure class (15+ instances)
3. **Ship-verification as a harness gate** on messages containing "done/shipped/landed" — content-based (blob SHA), not ancestry-based
4. **Doc-claim linter** (`check_rules.py`) — the instruction layer must be verified like code
5. **`measurement-stories.md`** generalized past ESG

### Tier 3 — The durable niche

Anthropic's own docs note task status **can lag** when teammates fail to mark tasks complete — exactly what `TaskCompleted`/`TeammateIdle` hooks exist to catch.

**peer-orchestra's defensible position is the enforcement and doctrine layer sitting on top of Anthropic's transport, not competing with it.** Native teams give you the plumbing; nothing native tells a team *how to work* — when to escalate, what a quality gate means, how to verify a claim of completion.

## Part 6 — What to preserve

Do not lose these in any rewrite:

- **Zero runtime dependencies, stdlib-only hooks** — no supply chain, minimal maintenance surface
- **Graceful degradation** — every hook try/except → exit 0. No hook can wedge a session
- **Preflight-before-write** — avoids the half-installed state
- **Reversibility** — a real `uninstall` with dry-run and surgical JSON/Markdown un-merge
- **Theme extensibility as pure data** — adding a theme requires no code
- **The persona content itself** — accumulated judgment from real sprints. Transport-independent; ports to any substrate unchanged

## Part 7 — Evidence from five months of real use

Mined from GCT's 50KB `lessons.md`, 12 battle-hardened personas, and 15 memory DBs. **Every gap below has a written rule that did not prevent the failure.** That is the finding.

### The five structural gaps

| # | Gap | Frequency | The rule that existed and didn't hold |
|---|---|---|---|
| **1** | **Shared working tree — no isolation** | 4+ incidents over 5 months | *"Only `git add` YOUR files by name — never `git add -A`"* (2026-03-24). Recurred anyway: a subagent **reverted another agent's `server.py` edit**; a concurrent session **swept an in-progress edit into its own commit** |
| **2** | **No probe-validity contract** | **15+ instances — the most frequent failure class** | *"When a probe and the system disagree, suspect the PROBE first"* — documented in the persona, **loaded in context, and not applied** |
| **3** | **"Done" unverifiable from inside the session** | 3 major | Rule 8 + the git verification table. A ship-language hook was **explicitly deferred** 2026-04-19 |
| **4** | **The instruction layer itself is unverified** | 3 false rules in one sweep | A command marked *"ALWAYS run for live data"* **had never run** (wrong directory depth) |
| **5** | **No orchestrator lease, no peer heartbeat** | 3 | *"ALWAYS check peer summary before dispatching."* **Two MOKAs double-dispatched**; messages to dead peers vanished silently |

### The three quotes that should shape v0.3

> **"8 hours of 'shipped' consensus against a working-tree hallucination."**
> Five agents reviewed ORCH-03a — authored, spot-checked, doc-committed, adversarially reviewed, infra-reviewed, with live F1 runs. **None caught that the classifier file was untracked.** Every verification step used filesystem signals. Shared tree = correlated observers, not independent ones.

> **"A metric that is bit-identical across four runs of a changing pipeline is not a measurement. It is a constant being re-read."**
> Stage-1 climbed 36.5%→78.8% across four runs while Stage-2 sat at *exactly* 2/52 every time. Caught by a parked agent reading artifacts, ~30 min before an expensive run — not by the author, orchestrator, or implementer.

> **"Having the anti-pattern rule in context does not mean it fires; the failure mode is not ignorance of the rule but not noticing the moment it applies."**

That last line is the design brief. GCT's rules total ~40KB; recall at the moment of relevance is near-random.

### What to convert from prose into execution

| GCT protocol | Verdict | Note |
|---|---|---|
| **`measurement-stories.md`** | **SHIP — the crown jewel** | Four questions (where is output *written*? what *reads* it? is the before-number live or frozen? what would prove this *didn't* work?). Prevents a whole class of expensive no-ops |
| **`check_rules.py`** (doc-claim linter) | **SHIP** | Pre-commit hook extracting every `path.ext` cited in a rule/persona and checking it against `git ls-files`. *"A wrong rule is worse than a missing one — it manufactures a fresh false finding at every review"* |
| **Save-on-Send** | **SHIP** | Write memory *before* sending a peer message, never at SessionEnd. GCT proved SessionEnd is unreliable for peers that finish and idle |
| **`team-dispatch.md`** | **SHIP as-is** | 4KB, every line earned. The Shared-File Sync Barrier is a real concurrency primitive |
| **Git verification table** | **SHIP** | Match the command to the lifecycle stage. Corollary: squash merges rewrite SHAs, so verify *content*, never ancestry |
| **`crash-resilience.md`** | **SHIP reduced** | Measured adoption: **one agent (Albedo) accounts for the majority of all three state-file types.** Honor-system protocols with single-agent uptake. Keep commit cadence + ship verification; drop the three overlapping hand-maintained state layers |

### The memory fix, precisely

- **KEEP** the schema — `superseded_by` is what makes the rolling pointer correct rather than junk
- **FIX** the extractor: it stores *inputs*. Require `{what_was_believed, what_was_true, how_it_was_detected, generalizable_rule}` — the shape the human-written lessons already use
- **DROP** the `quality-gate-*` namespace: 297 of 450 live rows, mostly non-reusable
- **ADD** a dead-agent signal: four personas stopped writing for months, silently

### The one-line brief

**The design question is not which rules to ship, but which of GCT's rules can be converted into things that execute** — worktree isolation, typed finding records, harness-side ship gates, a doc-claim linter, session leases. The rest is documentation, and five months of scars are the evidence that documentation alone does not hold.
